01 / Why OffGrid

A smaller brain.
Actually yours.

Cloud coding agents are excellent. They also cost money, need a connection, and send your code to someone else's computer.

OffGrid is the opposite trade: less raw horsepower, but it runs on your machine, works on a train, and never sends your repository anywhere by default.

“The interesting part is not the model. It is the orchestration.”

One local model, split into a team that plans, acts and checks.
  1. 01

    Plan the shape

    The planner breaks the task into 2–6 concrete steps, with files and dependencies, and assigns each one to a role.

  2. 02

    Do the work

    The coder reads before writing, edits narrowly, and runs what it can to check itself. The tester covers the change.

  3. 03

    Check the result

    The reviewer judges the diff. Your verification command runs. Failures go back to a coder until they pass or the run says so plainly.

02 / The team

Six roles.
One local model.

A 7B model asked to do everything wanders. The same model asked to implement one step, review a diff, or run a test does solid work. OffGrid does the splitting for it.

  • Lead

    01

    Coordinates the run and writes the closing report: what changed, how it was checked, and what remains.

  • Planner

    02

    Turns one request into ordered steps, each with a role, the files involved and its dependencies.

  • Coder

    03

    Full tool access. Reads first, edits narrowly, applies real patches and runs what it can to catch mistakes.

  • Tester

    04

    Writes or starts tests, prefers your existing runner, and reports the exact command and output.

  • Reviewer

    05

    Read-only judgement on correctness, completeness, safety and fit. It can approve or send the diff back.

  • Analyst

    06

    Read-only investigation for the steps that need understanding before anyone edits a file.

03 / What you get

Nothing leaves home
to get the work done.

A local model, real files, real commands, durable memory and a conservative shell policy. The useful parts of a coding agent without the cloud dependency.

  • 01

    Offline by default

    Loopback-only model endpoints unless you explicitly allow remote. --offline blocks network tools, package installs and remote git.

  • 02

    No meter running

    Local weights, no account, no API key, no quota and no per-token bill. Your hardware is the only thing doing the work.

  • 03

    Real edits, real checks

    Reads files, searches the repo, applies targeted edits, inspects git state and runs commands in the workspace.

  • 04

    Memory with provenance

    Durable notes with confidence and source. Your verification command is learned once. Shared lessons stay pending until you accept them.

  • 05

    Built to carry

    Pure Python 3.9+ standard library. Build a USB bundle with a portable runtime and model, then work with no install and no internet.

  • 06

    On your side

    Workspace-confined writes, a gated destructive-command list and a fixed loyalty order carried by every agent prompt.

04 / Quickstart

Three commands to a working team.

You need Python 3.9+ and a local OpenAI-compatible model server. Ollama is the shortest path. llama.cpp, LM Studio and vLLM work too.

No model yet? python3 -m offgrid demo runs a scripted end-to-end session without one.

Read the full quickstart ↗ Voice, USB builds and the rest ↗
01

Get a local model

ollama pull qwen2.5-coder:7b
ollama serve
02

Clone OffGrid

git clone https://github.com/experiencingtheview/offgrid.git
cd offgrid
03

Check, then build

python3 -m offgrid doctor
python3 -m offgrid chat
# or one-shot:
python3 -m offgrid run "fix the failing test"
